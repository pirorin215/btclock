## 設計思想

バイク版 `bikeclock/` と同じ寿命モデル（「乗っている間だけ通電」＝前機が8年ノーメンテだった理由）を、
キーオン電源の代わりに **18650直結 + 振動ウェイク** で再現する。
設計判断の背景は [`../DEVELOPMENT_BACKGROUND.md`](../DEVELOPMENT_BACKGROUND.md) 参照。

## 電源まわりの変遷(0.5mA 問題 → 待機 22µA)

1. **v0.4.9 時点の課題**: µA テスタ初実測で System OFF 中に 0.5mA が流れ続けていることが発覚
   (推定電池寿命 60 日)。テスト基板では ePaper リボン抜き・振動素子外しでも 499µA 不変
2. **真因**: WeAct ePaper モジュール基板(レベルシフタ+信号線プルアップ群)への常時給電。
   ファーム側の打ち手(hibernate 追加・信号ピン Hi-Z 化)では断てず 630µA までしか下がらない
3. **基準値**: 新品 XIAO 裸・BAT 直結で System OFF = 11µA(ボード無罪の確定)
4. **TPS22810(ロードスイッチ)での VCC カット**: 11µA まで下がることをテスト基板で実証したが、
   チャージポンプのスイッチングノイズが ePaper フル更新と相性不良(2回目以降の更新が
   Busy Timeout)で撤退。切り分け記録: [`../cycleclock_diag/AGENTS.md`](../cycleclock_diag/AGENTS.md)
5. **BSS138(N-ch MOSFET)ローサイドに落ち着く**(2026-10-07): GND 側を切る構成。
   単体試験(RDS 実測 2.6Ω)→実機組込。実機では 360µA までしか下がらず、切り分けの結果
   **残りの主犯は WS2812B の VDD 直結リーク(~330µA)** だった → ePaper と WS2812B の
   GND を同じ BSS138 の D へ共有接続して **22µA 到達**(0.5mA からの 2 日間の追跡)
   - 単体試験の手順・配線・AO3401A(P-ch ハイサイド)への移行手順:
     `~/www/kento/bss138-epaper-lowside-switch.html`
   - AO3401A は発注済みで、到着後に VCC 側統合(11µA+構造的頑健化)へ移行する選択肢が残っている

## 電源(充電)構成の変遷

- 当初は 18650 + ソーラー補助充電(TP4056 系モジュール経由)で構成していた(組立:
  `~/www/kento/xiao-ble-solar-tp4056.html`)
- 待機 22µA 達成後は電池が 3 年以上持つため**ソーラーは複雑さの割に不要**と判断して不使用に。
  18650 は BAT パッド直結(USB 充電は XIAO オンボード充電器)

## 振動センサーの変遷

- SW-18020P は「強いショックには確実・微振動に弱い」素子で、当初は自転車の乗り始めで起きなかった
  (ハンドルバッグを 50cm 落とすレベルが必要)
- **バネを筒の開口から引き出して伸ばす改造**(2026-10-05・メーカーの感度グレード
  (SW-18010P/15P/20P/25P=バネ長バリエーション)と同一軸の調整)で感度が 1〜2 桁改善し、
  乗り始めの振動で確実に起動するようになった。伸ばしすぎ/ひねりで静止導通が残ると
  寝られなくなるので、経年変化(さらに伸びる/絡む)は経過観察
- 代替案として GY-BMI160(any-motion 割込)の検証ファーム(`../cycleclock_vibetest/`)を用意済み

## スリープポリシーの変遷

- v0.3.0: 振動ベース(最終振動から3分)で寝る仕様
- v0.4.9: BLE 接続中は寝ない仕様を追加
- **v0.4.15(現行)**: 「BLE 未接続が1分続いたら System OFF」の1本に統一。振動センサーは
  System OFF からの復帰専用(起動後の D0 パルスは扱わない)。時計も時刻同期も接続ありき
  のため、接続の無い時間に起き続ける意味がない、という整理
- 残された課題: 「スマホが近くに居ると BLE が繋がったまま寝ない」(喫茶店問題)。
  原因はスマホ側アプリの接続維持であり、BTClockMob への RSSI しきい値接続の移植が
  解決策(自作ガリアアプリ `~/dev/Android/gardia_radar` に実績実装あり)

## その他の由来メモ

- LED の短パルス方式(ほぼ消灯+2秒に1回50ms)は自作キーボード界隈の「ほぼ消えているが
  生きている」LED 表現の流用
- バッテリーの「アイドル時キャッシュ測定」「BLE コールバックから analogRead しない」は
  fastrec2 での実測教訓
- SPI ピンを任意 GPIO に置ける構成(PSEL 割当・`SPI.setPins`)は nRF52840 の特徴で、
  ePaper 配線を物理配線どおりに割当可能にしている基盤
